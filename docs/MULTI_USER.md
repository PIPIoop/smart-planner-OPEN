# Многопользовательский режим Smart Planner

## Что реализовано

Smart Planner поддерживает несколько Telegram-пользователей с двумя ролями: `admin` и `user`. Каждый пользователь видит и изменяет только свой календарь. Администратор управляет доступом и видит служебную статистику, но Telegram-панель не показывает содержимое чужих задач.

Временный веб-интерфейс предназначен для локальной работы администратора. После отдельного входа он позволяет выбрать активного пользователя и открыть его изолированный календарь. Публиковать этот вариант в интернет нельзя до появления полноценной пользовательской веб-аутентификации.

## Хранение данных и миграция

- `services/task_api/data/users.sqlite3` — реестр пользователей, ролей и статусов.
- `services/task_api/data/tasks.sqlite3` — прежняя база задач; она без копирования становится календарём текущего администратора.
- `services/task_api/data/tenants/<sha256>.sqlite3` — отдельная SQLite-база каждого обычного пользователя. Telegram ID не раскрывается в имени файла.

Такое разделение не позволяет случайному запросу без `userId` смешать записи разных людей. Одинаковые ID задач допустимы в разных пользовательских базах.

## Регистрация в Telegram

1. Новый человек отправляет боту `/start`, текст или голосовое сообщение.
2. Бот создаёт заявку со статусом `pending` и сообщает пользователю, что требуется решение администратора.
3. Администратор получает сообщение с именем, username, Telegram ID и кнопками «Одобрить»/«Отклонить».
4. После одобрения пользователь получает статус `active` и может работать только со своим календарём.
5. При каждом обновлении бот проверяет актуальный статус до запуска остальных обработчиков.

Статусы:

- `pending` — заявка ожидает решения;
- `active` — доступ разрешён;
- `blocked` — временная блокировка;
- `deactivated` — аккаунт выключен, данные сохранены;
- `rejected` — заявка отклонена.

## Telegram-админ-панель

Команда `/admin` открывает список пользователей. Команда `/admin запрос` ищет по имени, username или Telegram ID.

Из карточки пользователя доступны:

- одобрение или повторная активация;
- отклонение заявки;
- блокировка;
- деактивация с сохранением данных;
- статистика количества задач, целей и групп;
- окончательное удаление аккаунта и отдельной SQLite-базы.

Полное удаление защищено двумя последовательными подтверждениями. Управлять аккаунтом администратора через эти операции запрещено на сервере.

## Защита API

`TASK_API_SERVICE_TOKEN` — мастер-секрет длиной не менее 32 символов. Он существует только в Task API и Telegram-боте и не передаётся во Flutter Web.

Для Telegram-запросов сервер и бот независимо вычисляют пользовательский HMAC-SHA256-токен из мастер-секрета и Telegram ID. Поэтому изменение одного заголовка `X-User-Id` не позволяет выдать себя за другого пользователя.

Для локального веба используется отдельный `TASK_API_WEB_ADMIN_PASSWORD`. После правильного пароля API выдаёт случайный серверный session token на 8 часов. Flutter хранит его только в памяти: после обновления вкладки требуется повторный вход. Администраторский мастер-токен не встраивается в JavaScript-сборку и не сохраняется в LocalStorage.

API слушает `127.0.0.1` по умолчанию, а CORS разрешает только локальные origin `localhost` и `127.0.0.1`.

## Настройки

В `services/tg_voice_bot/.env` обязательны:

```dotenv
TELEGRAM_ADMIN_USER_ID=123456789
TASK_API_SERVICE_TOKEN=replace-with-at-least-32-random-characters
TASK_API_WEB_ADMIN_PASSWORD=replace-with-a-separate-strong-web-password
```

Старое имя `TELEGRAM_OWNER_USER_ID` временно поддерживается как fallback, но новые установки должны использовать `TELEGRAM_ADMIN_USER_ID`.

## Локальный веб-доступ

1. Запустите `./run_task_api.ps1`.
2. Запустите `./run_web_with_api.ps1`.
3. На странице входа введите значение `TASK_API_WEB_ADMIN_PASSWORD` из локального `.env`.
4. В верхней панели выберите активного пользователя.

Переключение создаёт новое состояние календаря и заново загружает задачи, цели и группы выбранного пользователя. Фоновая синхронизация продолжает обновлять только текущий календарь каждые две секунды.

## Удаление и восстановление

Блокировка и деактивация обратимы: реестр и календарь сохраняются. Окончательное удаление удаляет запись реестра и файлы пользовательской SQLite-базы (`.sqlite3`, `-wal`, `-shm`) и не восстанавливается средствами приложения.

Календарь администратора (`tasks.sqlite3`) удалить через админ-панель нельзя. Это одновременно защищает прежние данные и исключает случайное самоудаление единственного администратора.
