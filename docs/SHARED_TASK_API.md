# Общий слой задач

## Зачем он нужен

Раньше Flutter сохранял задачи только в LocalStorage браузера, а Telegram-бот после кнопки «Да» лишь подтверждал распознавание. Они не имели общего источника данных. Теперь оба клиента используют один REST API и одну SQLite-базу.

```text
Telegram voice/text                    Flutter Web
        │                                  │
        │ POST create                      │ GET/POST/PUT/DELETE
        └──────────────┐       ┌───────────┘
                       ▼       ▼
                FastAPI Task API
                  /api/v1/tasks
                       │
                       ▼
                 SQLite tasks table
```

Клиенты не импортируют код друг друга. Общей границей является JSON-контракт. Поэтому бота, Flutter и хранилище можно развивать и тестировать независимо.

## Контракт задачи

```json
{
  "id": "stable-id",
  "title": "Позвонить врачу",
  "note": "Создано из Telegram",
  "date": "2026-08-10",
  "startMinute": 1110,
  "durationMinutes": 60,
  "priority": "normal",
  "isCompleted": false,
  "goalId": null,
  "goalOccurrenceDate": null,
  "completedAt": null,
  "groupId": null,
  "createdAt": "2026-08-03T10:00:00Z",
  "updatedAt": "2026-08-03T10:00:00Z"
}
```

`startMinute` — минуты от начала дня, от 0 до 1439, либо `null` для задачи на весь день. Приоритет: `low`, `normal` или `high`. Лимиты названия и описания совпадают с Dart-моделью: 120 и 1000 символов. Сервер генерирует ID и UTC-временные метки, если клиент их не передал.

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | готовность и версия схемы |
| `GET` | `/api/v1/tasks` | все задачи |
| `POST` | `/api/v1/tasks` | создать одну задачу |
| `PUT` | `/api/v1/tasks/{id}` | обновить одну задачу |
| `DELETE` | `/api/v1/tasks/{id}` | удалить одну задачу |
| `PUT` | `/api/v1/tasks` | атомарно заменить только список задач при импорте v1/очистке |
| `PUT` | `/api/v1/planner-data` | атомарно заменить задачи, цели и группы из резервной копии v2 |
| `GET` | `/api/v1/goals` | получить цели |
| `POST` | `/api/v1/goals` | атомарно создать цель и её задачи |
| `DELETE` | `/api/v1/goals/{id}` | удалить цель и связанные задачи |
| `GET` | `/api/v1/groups` | получить группы |
| `POST` | `/api/v1/groups` | создать группу |
| `PUT` | `/api/v1/groups/{id}` | изменить название или цвет |
| `DELETE` | `/api/v1/groups/{id}` | удалить группу, оставив задачи без группы |
| `POST` | `/api/v1/finance/payments/{id}/settle` | атомарно подтвердить оплату, создать расход и синхронизировать следующее напоминание |

Обычные действия Flutter используют операции над одной задачей. Это принципиально: старая полная запись списка могла затереть задачу, добавленную ботом после последней загрузки. Полная замена оставлена только для явно выбранных импорта и «удалить всё». Резервная копия schemaVersion 2 содержит `tasks`, `goals` и `groups`; перед записью проверяются уникальные ID, уникальные цвета и ссылки task→goal/group и goal→group. Удалённый режим применяет снимок одним `PUT /api/v1/planner-data` и одной SQLite-транзакцией. Старый schemaVersion 1 продолжает импортироваться как task-only формат.

Повторное создание с тем же ID и тем же содержимым идемпотентно. Telegram-клиент вычисляет стабильный UUID из chat ID, user ID и токена подтверждения: повтор после сетевого сбоя не создаёт копию.

## Telegram-поток

1. Бот получает текст или OGG voice.
2. VoiceTranscriber преобразует голос в текст.
3. TaskExtractor извлекает название, дату и время.
4. ConfirmationStore держит черновик 15 минут.
5. При «Да» TaskApiClient отправляет `POST /api/v1/tasks`.
6. Только после HTTP 201 черновик удаляется и бот сообщает «Задача сохранена».
7. При недоступном API черновик остаётся, поэтому пользователь может нажать «Да» повторно.

Исправлена обработка фраз вида «через два часа»: вычисленное `dateparser` время теперь не теряется.

## Режимы Flutter

- без `TASK_API_URL` — `LocalTaskRepository` и браузерный LocalStorage;
- с `--dart-define=TASK_API_URL=...` — `RemoteTaskRepository` и общий API.

В API-режиме bootstrap запускает фоновую синхронизацию раз в 2 секунды. Она обновляет только список в `PlannerViewModel`, поэтому страница, выбранная дата, поиск и обучение не перезапускаются. Если во время фонового GET начинается локальная запись, ответ с прежней ревизией отбрасывается и не может откатить только что сохранённую задачу.

Переключение сделано на этапе сборки, поэтому URL не хранится в исходниках production-сборки случайно. HTTP-клиент закрывается при уничтожении bootstrap-widget.

## Хранилище и параллельная работа

SQLite использует параметризованные запросы, транзакции контекстного менеджера и WAL. `replaceAll` удаляет и вставляет данные в одной транзакции, поэтому частично импортированного состояния не возникает. Оплата платежа резервирует один идемпотентный расход, меняет платёж и точечно заменяет только его служебные задачи; при ошибке все части откатываются. В локальном режиме все операции чтение-модификация-запись проходят через одну последовательную очередь. Индекс сортирует задачи по дате и времени.

API принимает CORS-запросы только от локальных `localhost`/`127.0.0.1`, что подходит текущему локальному Web-приложению. Для публикации потребуется явный список production-origin, HTTPS и аутентификация; сейчас API нельзя выставлять в интернет как публичный сервис.

## Конфигурация

Task API:

- `TASK_DB_PATH` — путь к SQLite;
- `TASK_API_HOST` — по умолчанию `127.0.0.1`;
- `TASK_API_PORT` — по умолчанию `8080`.

Telegram:

- `TASK_API_URL` — по умолчанию `http://127.0.0.1:8080`;
- `TASK_API_TIMEOUT_SECONDS` — по умолчанию 10;
- `APP_TIMEZONE` — часовой пояс разбора относительных дат.

Секрет Telegram остаётся только в игнорируемом `.env`.
## Контракт цели

Цель содержит обязательные `startDate` и `endDate`, шаг `intervalDays` и шаблон задачи (`taskTitle`, `taskNote`, `taskStartMinute`, `taskDurationMinutes`, `taskPriority`, `taskGroupId`). Клиент передаёт цель вместе со всем рассчитанным расписанием; сервис повторно вычисляет ожидаемые даты и отклоняет разрывы или несовпадение шаблона. SQLite записывает цель и задачи одной транзакцией. Максимум — 1000 повторений.

## Контракт группы

Группа имеет поля `id`, `name`, `colorHex`, `createdAt`, `updatedAt`. Цвет строго соответствует `#RRGGBB` и уникален на уровне SQLite. При удалении группы API одной транзакцией обнуляет `groupId` связанных задач и `taskGroupId` шаблонов целей, затем удаляет группу.

## Длительность и секретарь

Для задачи со временем `durationMinutes` обязателен логически: если клиент его не передал, API безопасно подставляет 60 минут. Допустимы значения 15–1440 минут с шагом 15; задача не может закончиться на следующие сутки. Для задачи на весь день оба поля — `startMinute` и `durationMinutes` — равны `null`. Миграция старой SQLite-базы назначает 60 минут прежним задачам со временем.

Telegram-секретарь остаётся детерминированным клиентом общего API: он не читает SQLite и не ведёт свободный LLM-диалог. Просмотр расписания, свободных окон и рекомендаций не меняет данные. Выполнение, перенос на следующий день, смена приоритета и удаление всегда проходят отдельный экран подтверждения. Перед созданием или переносом бот сверяет интервалы и предупреждает о накладках.
